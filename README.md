# ARGUS — АРМ чергового зміни

Виконала: А. Безносюк, слухач навчальної групи 231. Керівник: викладач кафедри № 22 л-т І. Курінний.

Курсова робота з дисципліни «Web-технології та Web-дизайн», тема 1: *автоматизоване робоче місце чергового зміни
центру моніторингу надводної та повітряної обстановки системи моніторингу морських і повітряних цілей (ARGUS)*.

Вебінтерфейс (React + IBM Carbon, тема Gray 100) з:

- **зведеною обстановкою** — надводні й повітряні цілі на одній карті (MapLibre), шари, картка цілі;
- **чергою подій** — пріоритет, нормативний час реагування (SLA), прострочені події, підтвердження з коментарем,
  керування з клавіатури (↑/↓, Enter, A — взяти в роботу, C — закрити);
- **журналом подій** — фільтри за статусом, пріоритетом, типом, пошук;
- **зміною** — приймання (обов’язкове ознайомлення з кожною незакритою подією) і передавання зі звітом,
  сформованим автоматично.

Реального сервера ARGUS немає, тому в `server/` — тестовий сервер (Node.js: REST + WebSocket), що імітує рух цілей,
події, джерела й звіти передавання зміни.

## Запуск

```bash
npm install
npm run dev        # тестовий сервер (4000) + Vite (5173) → http://localhost:5173
```

Вхід: оберіть чергового зі списку. Під час першого входу є звіт попередньої зміни на приймання (сторінка «Зміна»).
Для карти потрібен Інтернет (плитки OpenStreetMap). Змінні сервера: `ARGUS_PORT`, `ARGUS_SEED`, `ARGUS_SPEED`
(прискорення часу, за замовчуванням ×8).

| Команда | Призначення |
|---|---|
| `npm test` | автоматичні тести (Vitest) |
| `npm run lint` | ESLint |
| `npm run build` | збирання (Vite) |
| `npm run stories` | каталог компонентів (Ladle) |
| `node scripts/diagrams.mjs` | UML-діаграми записки (Mermaid → PNG) |
| `node scripts/screens.mjs` | знімки екрана записки (Playwright + Edge; потрібен свіжий сервер) |
| `python docs/zapiska/build_zapiska.py` | збирання `docs/zapiska/ZAPISKA.docx` (потрібен `python-docx`) |

Режим збою для перевірки станів: `POST /api/_chaos` з `{"mode":"error"|"slow"|"off"}`.

## Структура

```
src/views        представлення (Login, Picture, Events, Shift)
src/components   карта, черга подій, діалог, джерела, картка цілі
src/ui           оболонка, теги, стани (DataState), хуки
src/lib          чиста логіка: черга, SLA, звіт передавання
src/store.js     стан (Zustand)    src/api.js — REST    src/line.js — WebSocket
src/stories      каталог компонентів (Ladle)
server           тестовий сервер ARGUS
test             Vitest: логіка, компоненти, сервер, WebSocket
docs             пояснювальна записка (ДСТУ 3008:2015), рисунки, знімки екрана
```

Документи: `docs/zapiska/ZAPISKA.docx` — пояснювальна записка.

## Розгортання

Для розгорнутої версії один процес Node.js віддає і зібраний вебінтерфейс (`dist/`), і REST API та WebSocket —
усе на одній адресі, тому клієнт працює без змін (запити йдуть на `/api` і `/ws` того самого хоста).

```bash
npm install --include=dev && npm run build   # збирання вебінтерфейсу
npm start                                    # сервер: http://localhost:4000 (або порт зі змінної PORT)
```

Сайт розгорнуто на Render (безкоштовний план, Web Service, Node.js):

| Параметр | Значення |
|---|---|
| Build Command | `npm install --include=dev && npm run build` |
| Start Command | `npm start` |

Безкоштовний сервер засинає після 15 хвилин без відвідувачів; перше відкриття після цього триває до хвилини.
Стан тестового сервера (події, звіти зміни) зберігається в пам'яті й скидається після перезапуску.
